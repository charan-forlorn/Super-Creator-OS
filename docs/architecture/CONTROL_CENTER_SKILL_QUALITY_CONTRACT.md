# Control Center Skill Quality Contract\n\n## Purpose\n\nMission Control may surface reusable Skills with deterministic quality signals derived from the current SKILL.md bytes and adjacent resource directories. The quality registry is descriptive only. It does not promote, disable, execute, approve, or mutate a Skill.\n\n## Inputs\n\nscos.control_center.skill_quality.analyze_skill() reads only:\n\n- SKILL.md\n- the presence of scripts/\n- the presence of eferences/\n\nNo network call, subprocess, command execution, or repository mutation occurs.\n\n## States\n\nREADY means the Skill has a concise description/purpose and all routing, rules, required-output, and safety sections recognized by the analyzer.\n\nWARN means the Skill is readable but one or more quality signals are absent or the document is unusually long / structurally noisy.\n\nDEFECT means the Skill file is missing, unreadable, empty, or otherwise has a direct correctness defect detectable from the source bytes.\n\nThe registry must never turn WARN or DEFECT into an execution block unless a separate authoritative policy explicitly does so.\n\n## Signals\n\nThe analyzer reports:\n\n- description\n- when-to-use / routing\n- core rules\n- required output\n- safety / constraints\n- scripts directory\n- references directory\n\nWarnings include missing routing/rules/output sections, duplicate headings, and very long SKILL.md documents that may benefit from progressive disclosure.\n\n## Control Center boundary\n\nFloot only displays these signals. Skill execution remains outside the UI and continues to follow HAIOS/Hermes authority and approval boundaries.\n\n## Verification\n\nFocused tests live in:\n\nscos/control_center/tests/test_skill_quality.py\n\nThe module is intentionally deterministic and local-first.\n
